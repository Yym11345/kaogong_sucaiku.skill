# 抓取引擎参考

`kaogong.py` 本身只是入口，真正的抓取、清洗、打分都在主仓库的 `scraper` 包里。
本文说明它怎么工作，便于解释结果、判断异常。

## 数据流

```
八家媒体的电子版 / 频道页
        │  sources.LISTERS[媒体](date) → Article 列表
        ▼
   抓正文 + 清洗（去报头、责编、广告、副标题）
        │  sources.fetch_body → Article.body（≥150 字才留）
        ▼
   跨源转载去重（正文前 120 字指纹）
        │  run._dedup_body → 同一篇稿子只留一份
        ▼
   规则打分（五维，纯本地零成本）
        │  classify.classify → topics / tracks / score / reason / signals
        ▼
   SQLite（缓存目录 kaogong.db）
        │
        ├─ [--ai]   llm.analyze    → summary / angles / ai_score（计费，幂等）
        ├─ [--memo] llm.extract_memo → memorable 背诵段（计费，幂等，逐字校验）
        └─ [--deep] deepread.run   → deep_reads 速记卡（计费，幂等）
```

## 八个源

| 媒体 | 抓取方式 | 说明 |
|---|---|---|
| 人民日报 | 电子版按日期回溯 | 可抓任意历史日期 |
| 经济日报 | 电子版按日期回溯 | 同上 |
| 中国青年报 | 电子版按日期回溯 | 同上 |
| 光明网 | 时评频道 + 理论频道（`theory.gmw.cn`） | **只反映当前最新**，回溯多天不重复抓 |
| 半月谈 | 频道页 | 同上 |
| 求是网 | 首页 + 求是网评（`/qswp.htm`） | 同上。理论权威性最高，《求是》是习近平重要文章首发地之一 |
| 新华网 | 新华时评 + 新华社评论员 + 新华网评 + 评论频道 | 同上。四个页面合并，见下 |
| 人民网 | 观点频道页 | 同上。含人民日报评论员文章，量最大 |

「只反映当前最新」的五个源在 `--days > 1` 时只抓第一天，否则会把同一批文章
重复算到每一天。抓某个历史日期时，这些源可能没有对应内容，属正常。

**注意**：这五个源的日期全部取自 URL 路径（`/20261031/`、`/comments/20261028/`、
`/n1/2026/1030/`），不是抓取当天。`crawl_day` 会按 `--days` 窗口裁一遍，
所以 `--days 2` 时只留窗口内那两天——周末党媒不更新，最新稿常常是前一天的，
窗口太窄会让这类源整批落空。

### 栏目页比首页密得多

首页是编辑排的推荐位，位次有限、混着几个月前的旧稿。真正的日更在栏目页：

| 源 | 首页（不够用） | 栏目页（实际抓的） |
|---|---|---|
| 求是网 | `/`（55 条，七天内只有 11 条） | `/qswp.htm` 求是网评，日更一条 |
| 新华网 | `/comments/`（18 条，七天内只有 1 条） | `/depthobserve/xhsp.html` 新华时评、`/depthobserve/xhsply.html` 新华社评论员、`/comments/wpyc/index.html` 新华网评 |
| 光明网 | `/`（时评 18 条） | `guancha.gmw.cn` 时评 + `theory.gmw.cn` 理论 |

改完之后「`--days 7` 窗口内可用条数」：求是网 11 → 34，新华网 1 → 8，
光明网 18 → 68。

三个坑：

- **新华时评的稿子不挂在 `/comments/` 下**，散在 `/20261031/`、`/fortune/20261028/`
  各频道。用带 `/comments/` 的 `PAT_XINHUA` 一条都抓不到，栏目页必须用
  `PAT_XINHUA_ANY`（不限频道，只认 `/(年)(月)(日)/{hash}/c.html`）。
- **求是网栏目页用相对路径**（`20261031/{hex}/c.html`，没有前导斜杠），
  所以 `PAT_QSTHEORY` 的主机名部分是可选的。
- **光明网有一批 href 连前导斜杠都没有**（`2026-09/24/content_39019476.htm`）。
  `_channel_links` 必须**先 `urljoin` 再匹配正则**，直接拿 href 匹配会漏掉
  一大半（实测 18 条 vs 80 条）。

## 试过但没接的源

### 学习强国（xuexi.cn）

全站 SPA，HTML 只有 9 个中文字符，内容由登录态接口下发，还有阿里 CDN +
瑞数反爬。已实测：

- `/lgdata/index.json` 能拿到 2.3 MB 布局数据（含 331 个文章链接），
  但文章列表文件 `array-channel!*.json` 全部 404；
- 正文接口要 `checkSign` + 公钥签名，`needLogin` 判断在 vendor.js 里；
- headless Chrome 渲染后页面仍只有「学习强国」三个字。

结论：**纯 HTTP 抓不到，开浏览器也拿不到**。它的理论稿源与求是网、
时评稿源与新华网/人民网高度重合，用这三个源替代。

### 纯前端渲染的几家

同样试过，抓回来的是空壳（原始 HTML 里连 `<a` 都没有，正文由 JS 拼出来）：

| 站点 | 现象 |
|---|---|
| 央视网评 `news.cctv.com/opinion/` | 97 KB HTML，`<a` 计数 0 |
| 央视网评 `opinion.cctv.com/` | 只有 3 个锚点，340 处日期藏在 JS 字符串里 |
| 中新网评论 `chinanews.com.cn/comment/` | 101 个 `<a` 全是导航，列表走 JS |
| 人民网理论 `theory.people.com.cn/` | 236 个 href 全是导航 |
| 澎湃评论 `thepaper.cn` | 44 个锚点，正文走接口 |

这几家要接就得挂 headless 浏览器，与「每日定时任务只依赖标准库」的设计冲突
（`scraper/dom.py` 是手写的 100 行 DOM，不装 lxml/bs4），所以不接。

### 已经能替代的

- 央视网评的时政短评 → 新华时评 + 新华社评论员
- 人民网理论 → 求是网 + 光明网理论频道
- 中新网、澎湃 → 稿源与上述党媒高度重合

## 15 个议题

基层治理、乡村振兴、科技创新、营商环境、生态文明、文化自信、民生保障、
数字经济、法治建设、干部作风、舆情应对、对外开放、人口人才、安全底线、消费内需。

关键词命中不足 2 次的议题会被丢弃，避免「满屏安全底线」。都不命中归「综合」。

## 四类用途

| 用途 | 判定条件 |
|---|---|
| 申论素材 | 有明确议题，且文体分 ≥12 |
| 言语语料 | 300—1500 字，含排比或转折，语言分 ≥7 |
| 面试热点 | 有议题，且含转折/矛盾，或标题带「为何/如何/难题/困局」 |
| 常识时政 | 标题命中通稿动作或政策文件名（保持稀缺性） |

都不满足时标「泛时政」。

## 五维评分（满分 100）

| 维度 | 上限 | 看什么 |
|---|---|---|
| 来源 | 32 | 媒体基线（求是网 30、半月谈 28、人民日报 26、新华网 25、人民网 25、光明网 24、经济日报 23、中青报 22）+ 栏目加成 |
| 文体 | 24 | 政策文件、对策句密度、转折、字数（700—2600 字最优） |
| 话题 | 18 | 议题命中次数，最多取前 3 个 |
| 语言 | 12 | 数据、排比、成语密度 |
| 时效 | 10 | 1 天内 10 分，3 天内 8 分，7 天内 6 分 |

健康分布：均值 68—74，最高 90—95，90 分以上占比 <5%。
**分数只用于排序筛选，不代表真题命中率。**

## 三个计费环节的幂等标记

| 环节 | 标记列 | 非空即跳过 |
|---|---|---|
| AI 研判 | `ai_at` | 是 |
| 背诵提取 | `memorable` | 是 |
| 每日精读 | `deep_reads` 表按 (date, rank) | 是，`--force` 可重做 |

规则分与 AI 分分列存储（`rule_score` / `ai_score`），互不覆盖；
展示列 `score` 恒等于「有 AI 用 AI，没有用规则」。

## 背诵段的逐字校验

模型返回的段落会跟正文做整段比对，**一个字对不上就丢弃**。
所以 `memo` 输出的每段都能在原文里逐字找到——这对背诵是硬要求，
背下一段原刊里不存在的话比不背更糟。

## 缓存与保留

- 缓存位置：`%LOCALAPPDATA%\kaogong-skill\`（可用 `KAOGONG_DATA` 覆盖）
- `kaogong.db` + `covered.json`（记录哪些日期已抓过，避免重复抓空的日期）
- 每次 `fetch` 后按 `--keep`（默认等于 `--days`）清理超期文章
- 典型体积：79 篇 ≈ 0.5 MB；30 天全量 ≈ 20 MB

主仓库里的 `data/kaogong.db`（30 天全量）与 skill 缓存**完全独立**，
skill 不会读也不会写它。
